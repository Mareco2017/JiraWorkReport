## 3. 目标数据模型

```jsonc
{
  "id": "dd1dc1bb-…",
  "title": "EXEPD-205297 作业增加AI批阅功能",
  "status": "已完成",
  "completedAt": "2026-11-17T02:00:00.000Z",
  "workLogs": [
    {
      "id": "9f3c…",            // 稳定标识：草稿/回写/删除都靠它
      "day": "2026-11-16",
      "hours": 1.5,
      "state": "recorded",      // recorded | submitted
      "worklogId": "",          // 提交成功后的 JIRA 工时 ID
      "recordId": "",           // 对应批量记录 id（删除已登记笔时用）
      "targetKey": "",          // 实际写入的子任务号
      "submittedAt": "",
      "createdAt": "2026-11-17T02:00:00.000Z",
      "updatedAt": "2026-11-17T02:00:00.000Z"
    }
  ]
}
```

设计取舍：

- **每笔只保留日期与工时**（符合"记录日期+工时"的原始要求）。类型、工单、备注不再挂在待办上，避免两处真值。
- 汇总 = `sum(workLogs.hours)`；列表只显示这个数，**不标注"未登记"**（已确认）。
- 日期**允许未来**（已确认），只校验格式。
- 笔数上限 50（防御异常数据）。

## 4. 已实施项一：去兜底（现状确认）

- 来源页无兜底输入；`importTodos` 只收 `{ids}`；服务端不再调用 `agent.suggest`。
- **复审修正**：只有在待办本身记录了类型时才沿用，没有则空。当前实现即如此：

```js
const type = log?.type || '';      // 有则沿用，没有留空
const task = type ? typeMapping[type] || '' : '';
```

- 多笔化后：每笔没有类型字段，因此带入行的 `type` 恒为空，用户在第 2 步逐行选择；选中后自动匹配子任务工单（§5）。

## 5. 已实施项二：子任务工单自动带入（现状确认）

- 列名已改为「子任务工单」，日填报标签同步。
- 规则：行有工单 + 类型（推出子任务名）→ 在该工单已有子任务中按标题精确匹配：
  - 唯一命中：自动填入工单号，`subtaskSource='auto'`；
  - 多个同名：留空并提示手填；
  - 手填：`subtaskSource='manual'`，换工单/类型不覆盖；清空后重新自动匹配。
- 多笔改造**不需要动这套逻辑**：每笔行在选完类型后同样触发；同一待办的 N 行共享同一工单，`issueCache` 只请求一次。

### 5.6 新增改造点：子任务工单下拉选择

**目标**：日填报与批量填报的「子任务工单」，都能根据用户填写的工单，列出该工单下的子任务供下拉选择，不再要求用户记工单号。

**数据来源**：已有 `getIssue(key)` 返回 `subtasks[{id,key,title,typeId,status,statusCategory}]`（[app/jira.js](../../app/jira.js) `normalizeIssue`）。

**日填报**：

- 工单来源二选一：搜索选中（已有 `issueSelection`）或手工填写后失焦/变更时解析。
  - 未选中但输入框是合法 `KEY-数字`：`getIssue` 解析并缓存；失败不阻塞，仍可手填子任务号。
- 解析成功 → 「子任务工单」渲染为下拉：
  - 默认列出**未完成**子任务（`statusCategory!=='done'`），符合"当前用的子任务"；
  - **始终提供**「显示已完成」开关（已确认），勾选后追加已关闭/已完成项；
  - 首项固定为「自动匹配或创建「任务名」」，清空即返回自动。
- 月度任务（父单提交时才确定）：有月度绑定则解析绑定工单的下拉；没有绑定则保持手填输入框。
- 换工单/换类型：清空当前自动值并重新拉取；手填值保留并提示以子任务所属工单为准。

**批量填报**：

- 单元格保持可手填，输入框**右侧固定一个小 ▾ 按钮**（已确认，不采用"点击输入框弹出"）：
  - 点 ▾ 时按 `row.issue` 调 `getIssue`（沿用 `issueCache`，同一工单只请求一次）；点击输入框本身仍是正常编辑，不弹层；
  - 浮层列出未完成子任务（可切换显示已完成），支持按编号/标题筛选；
  - 选中写入 `subtaskKey/subtaskTitle`，`subtaskSource='manual'`；手输仍可直接改。
- 工单输入框失焦时若为合法编号且尚未解析，静默解析并写入缓存，供下拉使用（失败忽略）。
- **综合工时单行**：`row.issue` 为空，按当月绑定取父单；没有绑定则按月份调用 `searchMonthly` 找当月综合工时单；都取不到时提示"可先手填子任务号"（与日填报一致）。
- 现有自动匹配保留：无手填值时，选完类型仍按唯一同名自动填；下拉打开时高亮当前值。

**失败与边界**：子任务列表请求失败 → 只提示"无法读取子任务，可手动输入"，不阻塞；列表为空 → 只保留自动项与手输；已登记/已保存的值不受刷新影响。

## 6. 多笔工时设计（本轮重点）

### 6.1 命令与校验

| 命令 | 入参 | 规则 |
| --- | --- | --- |
| `todoAddWorkLog` | `{todoId, day, hours}` | 日期格式合法（允许未来）；0.25 步长；任意状态可加 |
| `todoUpdateWorkLog` | `{todoId, entryId, day?, hours?}` | 已 `submitted` 拒绝修改 |
| `todoDeleteWorkLog` | `{todoId, entryId}` | 未登记直接删；已登记需服务层先删远端（见 §7.3）；可删到 0 笔 |
| `todoComplete` | `{id, workLog?}` | 保留"顺手记一笔"：带 `{day,hours}` 时同时新增；不带则只完成 |
| `todoSetWorklog` | — | 删除（被上面三个命令取代） |

- 校验复用 `hoursValid/HOURS_ERROR`；`workLogs` 数组在 `validateTodoState` 中逐笔校验。
- 页面不能直接写 `state/worklogId/recordId/targetKey`，全部由主进程回写。

### 6.2 列表与详情

**列表**：行副标题只显示汇总 `工时 3.5 h`（不展示笔数、不加"未登记"，符合已确认决策）。

**详情**：

```
工时记录                         [＋ 记录工时]
─────────────────────────────────────────────
11月16日   1.5 h   未登记   [修改] [删除]
11月17日   2.0 h   已登记   [删除]（二次确认，连带删 JIRA）
合计 3.5 h
```

- 「记录工时」任何状态可用；对话框只有**工作日期 + 工时**两个字段，日期默认当天（可改，允许未来）。
- 已登记笔不可修改，但**可以删除**：二次确认后先删 JIRA 工时，再删本地笔。
- 完成待办的弹窗简化为"日期+工时"，日期默认当天，可跳过。

### 6.3 批量带入：按笔勾选（已确认）

已确认改为**按笔勾选**，与"带入待办的工时记录"一致；**未完成的待办同样可以带入**（只看是否有未登记笔，不再要求待办已完成），组头显示待办状态。

**列表结构**（来源页仍无分组说明与开关）：

```
┌ ☑ EXEPD-205297 作业增加AI批阅功能        3 笔 · 4.5 h ┐
│   ☑ 11月16日   1.5 h   未登记                          │
│   ☑ 11月17日   2.0 h   未登记                          │
│   ☐ 11月15日   1.0 h   已登记（隐藏/只读）              │
└────────────────────────────────────────────────────────┘
```

- 组头：待办标题 + 待办状态（已完成/进行中/待处理）+ **未登记工时合计**与笔数；组头复选框 = 全选该待办未登记笔。
- 子行：日期 + 工时 + 状态；勾选精确到笔。
- 已登记笔：默认不显示；即使显示也禁用、不可带入。
- 过滤：整条待办都没有未登记笔时整组隐藏（**笔级判断**，不能再用 `todo.workLog.state`）。
- 汇总条：`已选 N 笔 · 合计 X h`。
- 请求：`importTodos({entryIds:[...]})`；服务端按笔校验（不存在/已登记则整体拒绝并提示刷新）。
- 不带分组说明/开关，保持此前"文案精简"的结论。

> 关键修正（复审发现）：当前过滤是 `todo.workLog.state !== 'submitted'`，必须改为**笔级**判断：
> `(todo.workLogs||[]).some(e => e.state !== 'submitted')`，否则一笔已登记会让整条待办消失，其余未登记笔无法带入。

### 6.4 记录映射

| 记录字段 | 取自 |
| --- | --- |
| `id` | `sha256('todo-entry\n'+entry.id)` 前 24 位 |
| `todoId` / `todoEntryId` | 待办 id / 笔 id |
| `title` | 待办标题（作为工时备注） |
| `day` / `hours` | 该笔 |
| `type` / `task` | 空 / 空（等用户选择） |
| `issue` | 从标题解析当前项目工单号（解析不到为空） |
| `subtaskKey` | 初始空；用户选类型后由自动匹配填充 |
| `importSourceId` | `'todo:'+todoId`（保持现状） |

- 草稿去重继续用 `mergeDrafts`（按记录 id），同一笔重复带入不新增。

## 7. 身份、回写与同步

### 7.1 记录标识

- 记录 id：`hash('todo-entry\n'+entry.id)`；`importSourceId` 仍为 `'todo:'+todoId`。
- 已确认**不做旧数据迁移**，因此没有 `legacy` 身份特例；旧草稿保持原 id，不会被新逻辑引用。

### 7.2 提交回写（精确到笔）

- 批次项与历史记录增加 `todoEntryId`；`validateRecord` 原样透传未知字段，链路无需额外改造。
- `settleTodo(item)` 改为按 `todoId + todoEntryId` 标记，并写 `worklogId / recordId / targetKey / day`。
- `releaseTodo(record)` 按 `todoEntryId` 回退为 `recorded` 并清空上述字段。
- 旧的在途批次没有 `todoEntryId`：跳过回写，不影响提交本身（说明见 §11）。

### 7.3 已登记笔的删除

- 详情删除已登记笔 → 二次确认 → `SubmissionService.deleteRecord(entry.recordId)`（删远端、清历史、删草稿、标记批次项）→ 成功后移除本地笔。
- 远端失败或结果不确定：**不删本地笔**，错误原样提示。
- 缺少 `recordId`（例如迁移数据未关联）：提示"请到填报记录中删除"。

### 7.4 草稿同步

用户修改/删除**未登记**笔，而该笔已带入批量页（草稿 id 可算）时：

- 修改：同步草稿 `day/hours`。
- 删除：同步删除草稿。
- 由 `WorkbenchService` 执行（同时持有待办库与当前 scope 工作区），`PersonalTodoService` 不依赖 JIRA scope。

## 8. 旧数据：不保留（已确认）

- **不做迁移**：读取时直接忽略旧 `todo.workLog`，保存后字段自然消失；不写 `legacy` 身份分支。
- 影响：升级后旧单条工时不再显示在待办账本里；已提交到 JIRA 的工时仍然存在（在“填报记录”里可见/可删），只是待办侧不再持有链接。
- 旧草稿与旧批次不受影响，仍可正常提交；它们不会被新逻辑引用。
- 迁移相关的代码与测试全部不做。

### 10.2 新增用例

- 新增/修改/删除笔；0.25 校验；未来日期允许；删到 0 笔。
- 一笔已登记、一笔未登记：来源页仍显示，且只带入未登记那笔。
- 同一待办 3 笔 → 3 行，日期/工时各自对应，类型为空。
- 选类型后每行自动匹配子任务工单（唯一命中）；多个同名留空。
- 提交一笔 → 只该笔 `submitted`；删除填报记录 → 只回退该笔。
- 修改/删除未登记笔 → 草稿同步；已登记笔删除走远端，失败不删本地。
- 旧 `workLog` 不保留：读取后不显示、保存后字段消失；旧草稿仍可提交。
- **按笔勾选**：只勾 1 笔时只带入 1 行；组头全选只选未登记笔；已登记笔不可选。
- **子任务下拉（日填报）**：选中工单后列出子任务；默认不含已完成，打开开关后出现；选择写回草稿。
- **子任务下拉（批量）**：点开下拉拉取该工单子任务；同一工单多行只请求一次；选择后 `subtaskSource='manual'`；手输与自动匹配仍可用。
- 工单输入框手填（未走搜索）后失焦：能解析并填充下拉；解析失败不阻塞手输。

## 12. 验收标准

1. 待办可记录多笔工时，每笔仅日期+工时；列表只显示**汇总**。
2. 任意状态（含已完成）都能新增/修改/删除未登记笔；记录弹窗日期默认当天。
3. 详情展示工时列表，已登记笔不可改、可删（二次确认并连带删 JIRA）。
4. 批量来源页按**笔**勾选：组头全选只选未登记笔；已登记笔不可选、默认不显示。
5. 整条待办全部已登记时隐藏；部分已登记时仍显示，且只带入未登记笔。
6. 一条待办 N 笔 → N 行，工时/日期对应；类型为空由用户选择。
7. 日填报与批量填报的「子任务工单」都能从所填工单拉取子任务并下拉选择；默认不含已完成，可切换显示；手输与自动匹配仍可用。
8. 选类型后按现有规则自动带入子任务工单；手填不被覆盖。
9. 提交只回写对应笔；删除填报记录只回退对应笔。
10. 未登记笔的修改/删除同步草稿；已登记笔删除失败时本地不动。
11. 旧 `workLog` 不保留：升级后不再显示，且不影响旧草稿提交。
12. 现有 171 项通过用例保持通过（7 项 Windows 环境限制除外）。
